# 天策 AI 投研数字员工 v0.11.3｜Windows 首装与一句话安全更新正式版

一套运行在老板自己电脑上的投研工作台，而不是一张临时聊天页面。

它让三种入口共用同一套本地档案：

```text
网页连续对话 ───────────┐
专属工作区 Codex 对话 ──┼─→ research.db 统一可视化档案
定时自动汇报 ───────────┘          └─→ reports/ Markdown 报告
```

系统优先支持 A 股和港股，同时观察美股、日韩和全球宏观变化；按照“全球 → 市场 → 板块 → 公司”整理公开信息，并保留可点击来源。

它不接证券账户、不自动下单，也不提供个性化买卖指令、目标价或收益保证。

## 老板第一次怎么用

Windows：

1. 解压完整 Windows 交付包，打开 `product`；
2. 双击 `Windows_首次配置.cmd`，自动检查或安装 ChatGPT、Codex CLI、Python、投研插件和产品依赖；
3. 按浏览器提示用老板自己的 ChatGPT 账号登录 Codex；
4. 安装完成后网页会自动打开；以后双击 `Windows_启动研究台.cmd`；
5. 双击 `Windows_系统自检.cmd` 完成首次验收；
6. 希望登录 Windows 后自动运行，再双击 `Windows_安装开机自启.cmd`。

完整图文步骤和故障处理见 `Windows使用说明.md`。

Mac：

1. 如果拿到的是完整交付包，先双击相邻 `codex-plugin-marketplace/安装AI投研数字员工.command`；
2. 确认 Codex 已用 ChatGPT 账号登录；
3. 双击 `首次配置.command` 检查登录；API Key 可以不填，只作为备用；
4. 双击 `启动研究台.command`；
5. 浏览器自动打开 `http://127.0.0.1:8765`；
6. 填“老板偏好”，添加 3—10 家真正关注的公司；
7. 进入“连续对话”提问；想在 Codex 客户端用时，点“在 Codex 中打开”；
8. 希望登录电脑后自动运行，再双击 `安装开机常驻.command`。

只是看界面，可以双击 `演示研究台.command`。演示模式不会检索或虚构实时数据。

不再需要后台常驻时，双击 `卸载开机常驻.command`。这个动作不会删除对话、偏好和报告。

## 两个入口怎么用

- **网页端**：适合日常聊天、查看完整档案、管理自选公司和设置定时任务。
- **Codex 客户端**：适合深度研究和直接处理本机资料。必须从网页按钮打开，或把当前工作区设为本产品根目录。
- **统一档案**：网页消息当次写入本机档案；研究台运行时约每 5 秒导入一次 Codex 可见对话，不需要手动同步。

系统不会读取其他 Codex 项目。只有工作目录精确等于当前产品根目录的对话会被同步。

“在 Codex 中打开”不会自动替老板发送消息。它只会打开正确的产品工作区并预填启动语；老板点击发送后，研究台才会在后台同步该项目的可见问答。网页和 Codex 共用资料与档案，但不是两个实时共屏的聊天窗口。

## 公开投资框架怎么用

- 网页“公开框架”页保存公开材料入口和系统要追问的问题；
- 定时任务可以单独勾选“段永平公开方法”“但斌公开方法”；
- 输出只写“按公开方法还需要核验什么”，不得写成投资人本人的当前意见；
- 每次框架推演都必须注明：根据公开材料提炼，不代表本人真实看法，不构成投资建议。

## “越来越懂老板”是怎么实现的

```text
老板最新纠正
    ↓
已确认偏好与决策
    ↓
与当前问题相关的旧对话、旧报告
    ↓
待确认推测（只能询问，不能当事实）
```

完整消息负责“记得多”，相关检索负责“当前回答不混乱”。涉及价格、财务、政策和新闻的旧记录仍需重新联网核验。

## 数据和隐私

- 网页只监听 `127.0.0.1`，默认不能从局域网或公网访问；
- SQLite 数据位于 `投研数字员工/data/research.db`；
- 每日数据库快照位于 `投研数字员工/backups/`，默认保留最近 14 份；
- API Key（如果配置）只保存在本机 `.env`，不会返回网页，也不会写入数据库；
- API 调用使用 `store=False`，产品自己在本地维护多轮历史；
- 老板偏好和自选公司同时写入 SQLite 与 Markdown，网页和 Codex 修改后会在下一次研究前同步；
- Codex 对话同步只使用本产品的精确工作目录；工具调用、内部推理和其他项目对话不进入网页；
- 系统不会读取微信、通讯录、浏览器历史或证券账户；
- 模型会收到生成当前回答所需的老板偏好、自选公司和对话上下文；
- 不要输入账户密码、验证码、完整证券账号或无必要的精确仓位。

## 备份、恢复与迁移

- 研究台启动后每小时检查一次；当天还没有快照时，使用 SQLite 官方备份机制制作一致性快照；
- “老板偏好 → 本机备份 → 立即备份”可以随时手动生成一份，源库和快照都必须通过 `PRAGMA quick_check`；
- 恢复前必须先运行对应系统的“停止研究台”入口，再把当前 `投研数字员工/data/research.db` 另存一份，由人确认后用选定快照替换；产品不会在运行中静默覆盖；
- 完整迁移请复制整个 `投研数字员工/`。数据库保存统一档案，Markdown 文件保存老板说明书、自选公司、研究原则、决策、纠正、对话和报告的可读镜像；
- 交付给另一位用户时不要直接复制真实数据目录。运行 `生成老板交付包.command`，只交付 ZIP 和对应 `.sha256`，再核对校验值。

## 定时任务的真实边界

- 研究台进程必须运行，任务才会执行；
- 运行 Windows 或 Mac 的“启动研究台”入口后，即使关闭网页，进程仍在后台；
- 安装开机自启/开机常驻后，登录对应电脑账号会自动运行；
- 需要停用时运行对应系统的卸载入口，历史资料不会被删除；
- 关机、睡眠或断网期间不会运行；恢复后只补跑一份最近错过的正式计划，不回放离线期间的每个时点；
- 高频消息扫描会持续消耗 Codex 订阅额度或产生 API 费用，默认关闭；每日晨报默认启用；
- 建议先设置 07:00—23:00，试跑一周再决定是否提高频率。

## 双引擎是怎么工作的

`Codex 订阅优先（默认）`的顺序：

1. 本机 Codex 已通过 ChatGPT 登录时，使用订阅引擎；
2. Codex 不可用且 `.env` 配有 API Key 时，回退 OpenAI API；
3. 两个都没有时，明确提示配置，不会伪造实时报告。

Codex 和普通 ChatGPT 网页聊天不是同一条技术通道。本产品通过本机 Codex App Server 调用已登录的 Codex；订阅包含的 Codex 使用量仍受套餐额度限制。OpenAI API 是另一套按量计费账户，ChatGPT 订阅不会自动抵扣 API 费用。

Codex App Server 目前仍是实验性接口，因此本产品保留 API 回退。接口异常不会删除已经保存在本机的历史，稍后恢复时会继续自动归档。

## 电脑配置

普通办公电脑即可，不需要独立显卡，也不在本机运行大模型。本机只负责网页、SQLite 档案和任务调度，模型计算在 Codex 或 OpenAI 云端完成。需要 Python 3.11+、能正常运行 Codex 和浏览器，并保持足够的本地磁盘空间保存档案。

## OpenAI API 引擎

产品使用 OpenAI Responses API 和 `web_search`。正文引用和来源清单会明确展示。

- 默认模型：`gpt-5.6`；
- 对话与常规简报：low 推理、medium 搜索上下文；
- 公司深研：medium 推理、high 搜索上下文；
- 模型可在 `.env` 中通过 `OPENAI_MODEL` 更改；
- API 与网页搜索费用以老板自己的 API 控制台为准。

## 开发与测试

要求 Python 3.11+：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
.venv/bin/uvicorn app.main:app --reload --port 8765
```
