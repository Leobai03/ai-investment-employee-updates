# 长期记忆结构

## 目录

```text
投研数字员工/
├── 00_老板投资说明书.md
├── 01_自选公司.md
├── 02_重点板块.md
├── 03_研究原则.md
├── 04_决策日志.md
├── 05_待确认记忆.md
├── 06_老板纠正与反馈.md
├── inbox/
├── reports/
│   ├── daily/
│   ├── company/
│   ├── questions/
│   └── reviews/
└── sources/
```

## 什么写到哪里

- 市场、板块、周期、指标、风险和表达偏好：`00_老板投资说明书.md`
- 自选公司、代码、市场、最初理由、当前状态：`01_自选公司.md`
- 板块的关注理由、领先指标和跟踪频率：`02_重点板块.md`
- 已确认的研究方法与硬边界：`03_研究原则.md`
- 每次重要判断、后续结果和认知变化：`04_决策日志.md`
- 模型发现但老板尚未确认的偏好：`05_待确认记忆.md`
- 老板指出的误解、表达偏差和以后应避免的做法：`06_老板纠正与反馈.md`
- 老板临时放入的公告、会议纪要和材料：`inbox/`
- 正式报告：按类型和日期写入 `reports/`
- 需要本地留存的公开原始资料或来源索引：`sources/`

## 写入格式

所有长期条目至少包含：

```text
- 日期：
- 内容：
- 来源：老板明确说明 / 公开来源 / 系统待确认推测
- 状态：已确认 / 待确认 / 已失效
- 对以后研究的影响：
```

公司报告文件名：

```text
YYYY-MM-DD_市场_代码_公司名称.md
```

每日简报文件名：

```text
YYYY-MM-DD_每日简报.md
```

临时问答文件名：

```text
YYYY-MM-DD_问题关键词.md
```

## 更新规则

1. 先读取原文件，避免重复记录。
2. 用户纠正旧信息时，标记旧条目“已失效”，不要静默删除。
3. 相同偏好连续出现三次但未被明确确认，仍只能放入待确认文件。
4. 每周汇总一次重复记录；原始报告不删除。
5. 删除记忆必须由老板明确说出要删什么，并回显删除结果。
6. 迁移时复制整个目录；插件不代替备份。
